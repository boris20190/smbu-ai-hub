# new-api 部署指导

本文档基于仓库当前的 `Dockerfile`、`docker-compose.yml`、`new-api.service`、启动参数和初始化流程整理，面向生产或准生产环境部署。开发环境可参考 `docker-compose.dev.yml` 和 `makefile`，不要直接作为生产模板使用。

## 部署方式选择

| 方式 | 适用场景 | 主要文件 |
| --- | --- | --- |
| Docker Compose | 推荐的常规部署方式，适合单机部署并同时管理数据库和 Redis | `docker-compose.yml` |
| Docker 单容器 | 已有外部数据库或只想快速使用 SQLite | `Dockerfile`、官方镜像 |
| systemd 二进制部署 | 不使用容器，需要自行管理数据库、Redis、日志和进程 | `new-api.service` |
| 宝塔面板 | 使用面板运维的部署场景 | `docs/installation/BT.md` |

Kubernetes、Helm、云厂商托管模板不在本文档范围内。

## 前置要求

### 通用要求

* 服务默认监听 `3000` 端口，可通过 `PORT` 环境变量或 `--port` 参数调整。
* 生产环境建议使用反向代理接入 HTTPS，只在防火墙或安全组中开放必要端口。
* 首次部署后需要在 Web 界面完成初始化，创建管理员账号。
* 不要直接使用仓库示例中的数据库、Redis 或会话密钥口令。

### 数据库

new-api 支持三种数据库：

* SQLite：未设置 `SQL_DSN` 时启用。容器镜像工作目录为 `/data`，因此默认数据库文件会落在挂载的 `/data` 目录内。
* PostgreSQL：`SQL_DSN` 以 `postgres://` 或 `postgresql://` 开头时启用，仓库 Compose 默认使用 PostgreSQL 15。
* MySQL：其他非空 `SQL_DSN` 会按 MySQL 处理，项目要求 MySQL 版本不低于 5.7.8。

### Redis

未设置 `REDIS_CONN_STRING` 时 Redis 不启用。生产环境推荐启用 Redis，尤其是多实例部署或需要缓存同步时。使用 Redis 时应同时设置 `CRYPTO_SECRET`，多实例部署还必须保持所有实例的 `SESSION_SECRET` 一致。

## 关键配置

| 配置 | 说明 |
| --- | --- |
| `SESSION_SECRET` | 会话密钥。多实例部署必须一致；不要使用默认示例值。 |
| `CRYPTO_SECRET` | 加密密钥。使用 Redis 时应显式设置；未设置时会回退到 `SESSION_SECRET`。 |
| `SQL_DSN` | 主数据库连接字符串。留空时使用 SQLite。 |
| `LOG_SQL_DSN` | 日志数据库连接字符串。留空时日志使用主数据库。 |
| `REDIS_CONN_STRING` | Redis 连接字符串。留空时 Redis 关闭。 |
| `SQLITE_PATH` | SQLite 数据库路径。仅在使用 SQLite 且需要自定义路径时设置。 |
| `PORT` | HTTP 监听端口，优先级高于 `--port` 参数。 |
| `NODE_NAME` | 节点名称，容器或多节点部署时建议设置，便于审计日志区分来源。 |
| `NODE_TYPE` | 节点类型。非 `slave` 时为主节点；从节点不执行数据库迁移。 |
| `BATCH_UPDATE_ENABLED` | 设置为 `true` 时启用批量更新。 |
| `ERROR_LOG_ENABLED` | 设置为 `true` 时启用错误日志记录。 |
| `STREAMING_TIMEOUT` | 流式响应超时时间，单位秒。 |
| `MAX_REQUEST_BODY_MB` | 请求体最大大小，单位 MB。 |
| `STREAM_SCANNER_MAX_BUFFER_MB` | 流式扫描器单行最大缓冲，单位 MB。 |

应用启动时会尝试加载工作目录下的 `.env` 文件。容器部署通常直接在 Compose 中配置环境变量；二进制部署可使用 systemd 的 `Environment=` 或 `EnvironmentFile=` 管理。

## Docker Compose 部署

1. 准备目录并进入项目：

   ```bash
   git clone https://github.com/QuantumNous/new-api.git
   cd new-api
   ```

2. 编辑 `docker-compose.yml`：

   * 替换 PostgreSQL、Redis 和应用环境变量中的所有示例口令。
   * 保留 `./data:/data`，确保 SQLite、缓存文件等数据可持久化。
   * 保留或调整 `./logs:/app/logs`，方便收集应用日志。
   * 如果改用 MySQL，按文件顶部注释启用 `mysql` 服务、MySQL 版 `SQL_DSN` 和 `mysql_data` 卷，并停用 PostgreSQL 配置。
   * 多实例部署时取消 `SESSION_SECRET` 注释并设置为稳定随机值；使用 Redis 时设置 `CRYPTO_SECRET`。

3. 启动服务：

   ```bash
   docker compose up -d
   ```

   如果环境仍使用旧版 Compose 命令，也可以使用：

   ```bash
   docker-compose up -d
   ```

4. 查看状态和日志：

   ```bash
   docker compose ps
   docker compose logs -f new-api
   ```

5. 验证服务：

   ```bash
   curl http://127.0.0.1:3000/api/status
   ```

   返回 JSON 且 `success` 为 `true` 表示 HTTP 服务已启动。随后访问 `http://服务器地址:3000` 完成初始化。

## Docker 单容器部署

### SQLite 模式

适合快速部署或低并发单机使用。必须挂载 `/data`，否则容器重建后 SQLite 数据会丢失。

```bash
docker run --name new-api -d --restart always \
  -p 3000:3000 \
  -e TZ=Asia/Shanghai \
  -e SESSION_SECRET="<随机会话密钥>" \
  -v ./data:/data \
  calciumion/new-api:latest
```

### 外部数据库模式

已有 PostgreSQL、MySQL 或 Redis 时，可只运行应用容器：

```bash
docker run --name new-api -d --restart always \
  -p 3000:3000 \
  -e TZ=Asia/Shanghai \
  -e SESSION_SECRET="<随机会话密钥>" \
  -e CRYPTO_SECRET="<随机加密密钥>" \
  -e SQL_DSN="<数据库连接字符串>" \
  -e REDIS_CONN_STRING="<Redis 连接字符串>" \
  -v ./data:/data \
  -v ./logs:/app/logs \
  calciumion/new-api:latest --log-dir /app/logs
```

数据库和 Redis 地址必须从容器内部可访问。若数据库运行在宿主机，请按容器引擎和系统网络规则配置访问地址。

## systemd 二进制部署

systemd 部署适合不使用容器的服务器。需要先构建或获取包含前端静态资源的 `new-api` 二进制文件，并自行准备数据库和 Redis。

1. 构建前端和后端：

   ```bash
   make build-all-frontends
   go build -ldflags "-s -w" -o new-api
   ```

2. 准备运行目录：

   * 放置 `new-api` 二进制文件。
   * 创建数据目录和日志目录。
   * 如果使用 SQLite，确认 `WorkingDirectory` 或 `SQLITE_PATH` 指向可持久化的数据位置。

3. 参考仓库的 `new-api.service` 创建 systemd 单元，并替换用户、工作目录、二进制路径、日志目录和端口：

   ```ini
   [Unit]
   Description=New API Service
   After=network.target

   [Service]
   User=<运行用户>
   WorkingDirectory=<运行目录>
   Environment=SESSION_SECRET=<随机会话密钥>
   Environment=CRYPTO_SECRET=<随机加密密钥>
   Environment=SQL_DSN=<数据库连接字符串>
   Environment=REDIS_CONN_STRING=<Redis 连接字符串>
   ExecStart=<运行目录>/new-api --port 3000 --log-dir <日志目录>
   Restart=always
   RestartSec=5

   [Install]
   WantedBy=multi-user.target
   ```

   如果某个可选组件不使用，可以删除对应的 `Environment=` 行。不要把真实密钥提交到仓库。

4. 启动服务：

   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now new-api
   sudo systemctl status new-api
   ```

5. 查看日志：

   ```bash
   journalctl -u new-api -f
   ```

## 宝塔面板部署

宝塔面板部署已有专项文档：[BT.md](./BT.md)。使用宝塔应用商店或面板 Docker 功能部署时，也应设置 `SESSION_SECRET`；使用 Redis 时设置 `CRYPTO_SECRET`，并确保持久化数据目录。

## 首次初始化

服务启动后访问 Web 页面，系统会根据 `/api/setup` 状态引导初始化：

1. 创建管理员账号。
2. 选择自用模式或演示站点模式。
3. 完成初始化后进入控制台。

如果数据库中已经存在 root 用户或 setup 记录，系统会按已有状态进入，不会重复初始化。迁移旧数据前应先备份数据库。

## 反向代理与端口

生产环境建议由 Nginx、Caddy 或其他网关终止 HTTPS，然后反向代理到 `127.0.0.1:3000` 或容器映射端口。反向代理需支持流式响应，不要对 SSE 或长连接接口启用会破坏流式传输的缓冲策略。

只需要公网访问 Web 和 API 时，对外开放 HTTPS 端口即可；数据库和 Redis 不应直接暴露到公网。

## 升级

### Docker Compose

```bash
docker compose pull
docker compose up -d
docker compose logs -f new-api
```

升级前建议备份数据库和 `./data` 目录。若升级后异常，可切回上一个镜像标签并恢复备份。

### systemd

1. 停止服务：

   ```bash
   sudo systemctl stop new-api
   ```

2. 备份旧二进制、数据库和数据目录。
3. 替换为新二进制。
4. 启动并观察日志：

   ```bash
   sudo systemctl start new-api
   journalctl -u new-api -f
   ```

## 备份与恢复

至少备份以下内容：

* 主数据库：SQLite 文件、PostgreSQL 数据库或 MySQL 数据库。
* 日志数据库：如果设置了 `LOG_SQL_DSN`，单独备份日志数据库。
* 数据目录：Docker 默认是 `./data`，systemd 部署按实际 `WorkingDirectory` 或 `SQLITE_PATH` 决定。
* Compose 配置或 systemd 环境配置：只保存到安全位置，不提交真实密钥。

恢复时先停止应用，再恢复数据库和数据目录，确认环境变量与恢复的数据匹配后启动服务。

## 常见问题

### `/api/status` 无法访问

检查容器或 systemd 服务是否运行，确认端口映射、防火墙和反向代理配置正确。容器部署可查看：

```bash
docker compose ps
docker compose logs new-api
```

### 登录状态不稳定

检查 `SESSION_SECRET` 是否固定。多实例部署必须使用同一个 `SESSION_SECRET`，不要每次启动都生成新值。

### Redis 连接失败

检查 `REDIS_CONN_STRING` 格式、密码和网络连通性。启用 Redis 时应设置 `CRYPTO_SECRET`，并确保所有实例使用一致的值。

### 数据库迁移或连接失败

检查 `SQL_DSN` 类型和数据库版本。PostgreSQL 连接字符串需要以 `postgres://` 或 `postgresql://` 开头；MySQL 需满足项目版本要求。主节点会执行数据库迁移，从节点不会执行迁移。

### SQLite 数据丢失

确认容器部署挂载了 `/data`，systemd 部署确认 `WorkingDirectory` 或 `SQLITE_PATH` 位于持久化目录。不要把 SQLite 数据保存在临时目录。

### 流式响应中断或空响应

检查反向代理是否启用了影响 SSE 的缓冲或超时设置。必要时调大 `STREAMING_TIMEOUT`，并结合应用日志确认上游模型渠道是否正常。
